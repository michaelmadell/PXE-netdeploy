### Backend: `GET /system/interfaces`

- Operation `listHostInterfaces`; schemas `HostInterface` (`name`, `mac`,
  `addresses[]`, `up`, `loopback`) and `HostInterfaceAddress` (`address`,
  `prefixLength`). IPv4 only, read from the OS on every call.
- `settings.HostInterface` gained `MAC`, `Up`, `Loopback`.
  `settings.HostLister` is the new interface; `SystemHost.Interfaces()`
  implements it. `server.Deps.Host` injects it (nil means `SystemHost`).
- `name` is Go's `net.Interface.Name`: the friendly name on Windows, the
  device name on Linux. No hardware description.

## Conventions the UI follows

Keep to these when adding pages.

- **No new npm dependencies** were added and `pnpm-lock.yaml` is unchanged.
  Check with the user before adding any.
- **Query keys:** `["health"]`, `["settings"]`, `["host-interfaces"]`,
  `["capabilities"]`, `["images"]`, `["images", id]`, `["uploads"]`,
  `["boot-images"]`, `["boot-images", id]`, `["profiles"]`,
  `["driver-groups"]`, `["jobs", kind, "active"]`. `lib/events.ts`
  invalidates by these prefixes; a new resource needs a case there.
- **Errors:** call `unwrap(await api.X(...))` so failures throw `ApiError`.
  Wrap a form in `<FieldErrors value={error.fields}>` and give each `Field`
  the API `path` (`interfaces[0].dhcp.pool.start`) to show server field
  errors beside the control.
- **Mutations of existing resources** send `If-Match` with the resource's
  `etag`; 412 is shown as "changed somewhere else".
- **Idempotency keys:** a 4xx answer is replayed for its key, so take a new
  key after a refusal (`newKey()` in `images/data.ts`; it avoids
  `crypto.randomUUID`, which needs a secure context).
- **Partial forms round-trip the rest.** Settings sends back `backup`,
  `contentHttps` and the admin certificate untouched. The boot image form
  keeps `tftp`, `agentVersion`, `optionalComponents`. The profile form keeps
  `identity`, `variables`, `osSettings` and strips `id`, `etag`,
  `createdAt`, `updatedAt` before the `PUT`.
- **Copy:** plain words for an operator, not API terms: "Out of date" for
  `stale`, "Not built" for `draft`. Status is a dot plus text, never colour
  alone. Every destructive action has a confirm dialog that says what is
  kept.

## Behaviour worth knowing

- **Settings draft:** `base` is the server copy the draft came from.
  `toRequest()` strips editing conveniences (a pool is kept in the draft
  while the DHCP mode is switched; only `full` sends one). A
  `settings.updated` event while the form is dirty offers a reload instead
  of overwriting edits.
- **Adapter picker** falls back to a typed name if `/system/interfaces`
  fails. Adapters already used by another interface card are disabled.
- **Server addresses** for a boot image are suggested from settings: one
  `http://<advertisedAddress or adapter's first IPv4>[:port]` per interface
  with HTTP on. They are baked into the image.
- **Readiness** (Overview) checks five things: an interface with TFTP or
  HTTP on, a ready Windows image, a boot image with artifacts, a default
  profile whose boot image is built, and that some interface has HTTP on a
  port named in that boot image's `serverUrls`.
- **Build button:** `force: true` only when the boot image is already
  `ready`; otherwise the server may answer 200 "already up to date", which
  the detail page says in words.
- **Profiles created in the UI** are `installMethod: agent`,
  `identity: { mode: "none", skipEula: true }`.
